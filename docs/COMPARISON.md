# 对比：RLS vs 常见方案

| 维度 | grep / rg | VS Code 跳转 | 向量/embedding 搜索 | RLS |
| --- | --- | --- | --- | --- |
| 返回 | 文本行 | 单点跳转 | 相似片段（黑盒） | 文件+符号+行号+调用关系+快照 |
| 服务对象 | 人 | 一个人 | Agent（要调模型） | CLI 人 + MCP 的 AI，共索引 |
| 部署 | 单文件 | IDE | 模型+向量库+服务 | 单文件 `rls.exe`，零模型依赖 |
| 隐私 | 本地 | 本地 | 常上云 | 本地，默认 127.0.0.1 |
| 结果可核对 | 需人工翻 | 可 | 难 | 带 file:line+snapshot，可写进记录 |
| Token 成本 | 高（Grep→Read×N） | 中 | 中高 | 低（先定位再深读，compact 受限） |

**一句话**：grep 告诉你“字在哪”，RLS 告诉你“定义在哪、谁调它、影响哪、证据在哪”。
