# 实测效果与复现（Benchmarks）

> 以下是一次 Windows x64 实测，不是承诺。你的机器/仓库规模不同，数字会变。方法公开，可自己跑。

## 一次 p95（50 Rust 文件，预热 5 次，采样 30 次）

| 场景 | p95 |
| --- | ---: |
| 冷启动建索引 | 53.61 ms |
| 暖查询（索引已在） | 20.27 ms |
| 无变化重复检查 | 20.30 ms |
| 单文件变更后刷新 | 42.03 ms |
| 精确搜索 | 3.74 ms |
| `trace` 4K 受限输出 | 29.93 ms（约 928 Token） |

## 规模扩展（同套基准，生成样例）

| 规模 | 冷启动 p95 | 暖查询 p95 | 单文件变更 p95 |
| --- | --- | --- | --- |
| 500 文件 | 324 ms | 27 ms | 97 ms |
| 5,000 文件 | 2.96 s | 91 ms | 1.11 s |

## Token 节省估算（固定任务样例）

| 环节 | 省 |
| --- | --- |
| 精确搜索+补读 | 约 84.5% |
| 目录概览 | 约 85.9% |
| 深入查看 | 约 95.0% |
| 合计 | 约 91.3% |

**解读**：省的不是“搜索本身”，省的是“因为定位准而少读的文件”。`--compact` 与受限 `trace` 会进一步压 payload。

## 自己复现

1. 用 Release 包跑 `rls doctor --json` 确认环境。
2. 找一个中等仓库，先 `rls outline <dir> --max-files 100` 建地图。
3. 记录两组数：A 组直接 Grep+Read 完成任务的轮次/token，B 组按 [BEST-PRACTICES](BEST-PRACTICES.md) 走 RLS。
4. 发 Issue 时贴：文件数、语言构成、`doctor --json`、两组数。我们只认可带复现步骤的数字。

## 我们不承诺什么

* 不承诺任何仓库都省 91.3%。
* 不承诺语义理解、跨语言推理 100% 准确；`candidate/unresolved` 必须回源码确认。
* 不承诺 macOS/Linux 首发包时间——看 Issue 投票。
